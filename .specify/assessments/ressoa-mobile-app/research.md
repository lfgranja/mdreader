## Market & Context

- Users cope today with built-in Android TTS, screen readers, or produced audio (podcasts/audiobooks); none combine Markdown-native reading with content-fingerprinted resume, closed rate ladder, classified focus response, and a non-invasive lock-screen — per the project's own differentiation claims. — [source: `.agents/product-marketing.md` §§3–4; ASSUMPTION for the "none combine" breadth — no comparative test in repo] (confidence: low) (assumption)
- Distribution intent is F-Droid, not Play Store (no 30% fee, open-source aligned); launch strategy is explicitly "do not launch yet" — launch only after real audio + lock-screen notification demo on device. — [source: `.agents/product-marketing.md` §§8–9; `RELATORIO_BRAND_PRODUTO.md` §4, cited] (confidence: high)

## Data & Constraints

- **Platform floor:** Android 10 (API 29) minimum through Android 14+ FGS-start restrictions; reference device Redmi 2201117TY (Android 13/API 33) is normative for latency verdicts. — [source: `specs/001-android-media-shell/spec.md:39` + `plan.md` Technical Context/Reference device, cited] (confidence: high)
- **Audio handoff (closed):** engine delivers mono f32 at declared 22050 Hz; mismatch is a named `EngineError`, never silent resample. — [source: `spec.md:27,75`; `plan.md` Constraints; `constitution.md` Audio Pipeline Contracts, cited] (confidence: high)
- **Performance bounds:** play-to-audio ≤3 s (spec clarification) / ≤10 s cold-start on reference phone (plan); headphone-pull pause ≤1 s; skip exactly ±5 s; rate change ≤2 s; pre-roll ≤60 s drained while idle; kill replay ≤30 s; transient rewind 5%-of-pause capped at 30 s with paragraph/heading snap. — [source: `spec.md` clarifications; `plan.md` Performance Goals, cited] (confidence: high)
- **Closed sets everywhere:** 7 rate rungs `[0.75, 1.0, 1.25, 1.5, 1.75, 2.0, 4.0]`; focus outcomes; transport states; error kinds (`EngineError` 7 members); session-end reasons; no `_ =>`, no `Other`. Extension = coordinated edit + semver bump + docs. — [source: `spec.md:77`; `constitution.md` Principle VII + gate 7, cited] (confidence: high)
- **Notification surface limits (documented, not eliminated):** OEM relayout (Samsung/One UI, Xiaomi/HyperOS) — encode state by shape+position, not color alone (R2); Android 13+ derives compact controls from PlaybackState, 5 slots — Stop may be expanded-only (R3); Android 16 Live Updates forbid customContentView — standard MediaStyle only (R4); marquee/reason-moving-text impossible on MediaStyle — static reason + dot + earcon + 3 s TTL, scroll only in-app (R1). — [source: `DESIGN-SONA/risks.md` R1–R4, cited] (confidence: high)
- **Diagnostic record:** append-only JSONL in app-private storage, 30-day + 10 MB oldest-first trim, never transmitted, no in-app surface, no document text in any entry (`detail` ≤200 chars identifier-pattern or typed fields; `error` required on `failure` and `refusal`). — [source: `spec.md:38,43,62,79–80`; `plan.md` Storage/Constraints, cited] (confidence: high)
- **Governance gates:** `scripts/verify.sh` gates 1–9 (format, nextest, doc, lint-drift, supply-chain deny+audit, deny-list, closed-set, pipeline, android-build) fail closed; Rust rigor denies unsafe/unwrap/expect/panic/todo/println with only `#[expect(reason)]` suppression; supply chain requires latest-stable, crates.io-only, `--locked`, advisory-free (with two recorded waivers). — [source: `constitution.md` Principles IV–V, Rust Code Rigor, Verification Gates, Exceptions Log 9–10, cited] (confidence: high)
- **Consent/sovereignty:** no secrets in repo/binary; per-provider revocable consent for any cloud egress; Edge endpoint is consent-gated fallback-last, never default, never via the OpenAI-compatible Python wrapper. — [source: `constitution.md` Principles X–XI + Engine Registry, cited] (confidence: high)
- **Out of scope (recorded):** Android Auto (no TTS category); light mode (dark-only specified); in-app diagnostic screen / export (deferred). — [source: `constitution.md` Tauri Platform Contract; `DESIGN-SONA/tokens.md` §5; `spec.md:51`, cited] (confidence: high)

## Evidence Against the Idea

- **No external demand signal:** the only user evidence is the maintainer's own spec and dogfooding intent; shipping a "real app" (signing, store/F-Droid listing, support surface) without any external reader asking multiplies maintenance without validating anyone wants it. — [source: `.agents/product-marketing.md` status line; intake Origin NEEDS CLARIFICATION, cited] (confidence: medium)
- **Real audio is not done:** 002 adapter tasks show core built (T1–T8 per 002 tasks head) but SC-044 stays DEFERRED and gate-8-full stays DEFERRED; a DESIGN-SONA app shell without synthesis is still a silent mechanism. — [source: `specs/002-fr-024-synthesis-adapter/tasks.md`; `constitution.md` Exceptions Log 8, cited] (confidence: high)
- **Known 001 gaps sit on the exact path a "real app" needs:** duck gain not yet applied to audible PCM, focus/offer latch stateless on the bridge, no Rust→shell publish path — all open in Phase 13 (T122–T127). — [source: `specs/001-android-media-shell/tasks.md` Phase 13, cited] (confidence: high)
- **On-device proof is deferred:** the 10/10 trials (lock-screen, focus, routing, play-to-audio, failover) are hardware-gated and unattested in VERIFICATION (host-only PASS + DEFERRED labels); OEM relayout and slot limits could still degrade the driver-visible surface. — [source: `specs/001-android-media-shell/VERIFICATION.md` attestation rule; `DESIGN-SONA/risks.md` R2–R4, cited] (confidence: high)
- **Latency/voice quality unverified on reference hardware:** ≤3 s first audio and cabin intelligibility for Piper pt-BR local voices have no measured evidence in-repo; prior assessment flagged both. — [source: `.specify/assessments/fr-024-synthesis-adapter/research.md` Evidence Against, cited] (confidence: medium)
- **"Real" is undefined:** F-Droid repo vs. public submission vs. sideloaded APK, signing, versioning, changelog, privacy posture, and support channel are all undecided; each is a commitment, not just a build flag. — [source: ASSUMPTION from absence — no distribution checklist found in repo] (confidence: medium) (assumption)
- **Design-implementation skew risk:** DESIGN-SONA softens candidate-B discipline (turquoise/gold/violet, envelope strip, gesture extensions) while the shell was specified against B-era constraints; R9–R12 (LoL confusion, washed palette, pretty-but-not-functional, sound dependence) are documented but untested. — [source: `DESIGN-SONA/DESIGN-SONA.md` §§2, 8 + R9–R12, cited] (confidence: medium)
