## Notes

- This checklist validates data / segment / resume *requirements*, not `DocumentSegment` implementation, `chunk.rs` code, or `redb` bookmark storage. Verification that segments split correctly, resume to correct boundary, and `blake3` invalidates position on edit belongs to implementation / gate verification (`verify.sh`, on-device trial), not to this requirements-quality check.
- `SC-044` deferred means active multi-engine fallback with new-engine resume is not fully required for v1 — but the *mechanism preserving* resume behavior (`FR-023a`, `FR-036`, `adapter-handoff.md:4`) must be clearly specified now, so that `SC-044` discharge only needs second engine registration + selection logic, not new resume design.
- `pulldown-cmark` reachability (clarification C4-A) is a dependency gate: if unreachable when `003-contract-edit` lands, adapter split logic design must adapt; requirements should not assume unreachable dependency as permanently unavailable.
- All 7 `EngineError` variants (no `AdapterFailed`, no `parse` kind in v1) preserved; `bad Markdown` = document/parse-level; `diag` schema deferred to coordinated `FR-044` edit (`spec.md:85` / clarification C4-A).
