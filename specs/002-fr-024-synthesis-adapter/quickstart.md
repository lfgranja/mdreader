### Scenario A — Capability Declaration (`FR-024c` / Contract `adapter-capabilities.md`)

**What it proves**: Adapter declares `(None, None)` unconditionally; no phantom trait methods; `player` branches correctly.

**Prerequisites**:
- `crates/engine-core/src/lib.rs` unchanged (no `trait_.rs` created prematurely — `Assumption 3` corrected).
- `SsmlLevel` and `AlignmentGranularity` are defined in `src/lib.rs` (adapter-defined, re-exported at the crate root) — closed three-member sets, no `Other`/`Unknown`.

**Commands / checks**:

**Reference**: `contracts/adapter-capabilities.md` §2–§3; `spec.md:97`; `constitution.md:304-305`; `research.md` §3.3.

### Scenario B — Chunk Split at Paragraph / Heading (`FR-024a` / Data Model E1)

**What it proves**: Adapter owns chunk boundary; engine does not independently resample/split; chunk budget ≤5000 bytes enforced adapter-side.

**Prerequisites**:
- **No Markdown parser dependency.** `src/chunk.rs` is a deliberate line scan (ATX `#` headings only, 1–6 hashes after ≤3 leading spaces). Setext headings, `#` lines inside fenced code blocks, list items and block quotes are mislabelled `Paragraph` — the recorded line-scan deviation (`API_CONTRACT.md` §2.1a; task T034), pinned by `tests/prop_segmentation_shapes.rs`. `pulldown-cmark` is **not** a dependency of this crate.
- Test Markdown documents with paragraph + heading structures are generated by the proptest strategies in `tests/prop_chunk.rs` / `prop_chunk_refined.rs`.

**Commands / checks**:
```sh
# Byte budget: MAX_CHUNK_BYTES is exactly 5000 and is a hard bound (bytes, not chars)
cargo nextest run --locked -p adapter-synthesis max_chunk_bytes_is_exactly_5000
cargo nextest run --locked -p adapter-synthesis every_segment_stays_within_the_5000_byte_budget
cargo nextest run --locked -p adapter-synthesis no_segment_ever_exceeds_a_randomly_chosen_budget

# Boundary behaviour: exact fit, one-byte overflow, char-safe hard split
cargo nextest run --locked -p adapter-synthesis exact_fit_at_max_chunk_bytes_yields_exactly_one_segment
cargo nextest run --locked -p adapter-synthesis one_byte_over_max_chunk_bytes_yields_two_bounded_segments

# The deliberate line-scan deviation, pinned (§2.1a)
cargo nextest run --locked -p adapter-synthesis setext_headings_are_paragraphs_not_headings
cargo nextest run --locked -p adapter-synthesis hash_lines_inside_fenced_code_blocks_open_heading_blocks
cargo nextest run --locked -p adapter-synthesis list_items_are_paragraphs_not_headings
cargo nextest run --locked -p adapter-synthesis block_quote_lines_are_paragraphs_not_headings

# CLI: the same split — segment metadata only, never segment content (FR-045)
printf '# Title\n\nFirst para.\n\nSecond para here.\n' | cargo run --locked -p adapter-synthesis -- chunk
# → {"capability":"split_document","segment_count":2,"segments":[{"segment_index":0,"line_start":1,"line_end":3,"boundary_kind":"heading","byte_length":20,"resume_point":{"line_start":1,"line_end":3}},{"segment_index":1,"line_start":5,"line_end":5,"boundary_kind":"paragraph","byte_length":17,"resume_point":{"line_start":5,"line_end":5}}]}  (exit 0)
```

**Expected outcome** (all nine `nextest` filters pass on this host):
- Every output `DocumentSegment.byte_length ≤ 5000` (UTF-8 byte count, not char count — `constitution.md:353`).
- Boundary kind = `Paragraph` or `Heading` (never `Sentence` — `AlignmentGranularity::None`).
- `source_range` preserved for each chunk (resume mapping possible); `resume_point` is always `Some(source_range)`.
- Engine receives bounded chunks; does not independently split (contract rule from `adapter-handoff.md` §2.1).

**Reference**: `data-model.md` E1 (validation rules R3, R4); `spec.md:19`; `CLARIFICATION_BATCH.md` C3-A; `constitution.md:353`.

### Scenario C — Format Delivery & Named Failure (`FR-024b` / `SC-035` / Contract `adapter-handoff.md` §2–§3)

**What it proves**: Adapter delivers mono f32 @ 22050 Hz; any deviation surfaces named `EngineError`; never silent resample; `SC-051` mechanism preserved.

**Prerequisites**:
- `sherpa-onnx` **1.13.8** + the embedded Piper pt-BR `faber` voice **are bound** in this crate (T044; `API_CONTRACT.md` §7/§7.1). `src/synth.rs` loads the engine once per process (`OnceLock`) and synthesizes each bounded segment to mono `f32` @ 22 050 Hz; a load failure, an empty result, an interior NUL (FFI transport) or a process death each names a closed-set member through `EngineFailure::report` — never an empty buffer, never a silent resample.
- `crates/engine-core/src/format.rs` unchanged (`DeclaredFormat` preserved — `SAMPLE_RATE` 22 050, `CHANNELS` 1, `SAMPLE_WIDTH_BITS` 32).

**Commands / checks**:
```sh
# Happy path — exactly the declared shape passes
cargo nextest run --locked -p adapter-synthesis exactly_the_declared_shape_is_ok
cargo nextest run --locked -p adapter-synthesis the_declared_shape_with_a_consistent_length_is_delivered

# Failure paths — named EngineError, never a silent resample/downmix
cargo nextest run --locked -p adapter-synthesis a_rate_deviation_alone_names_rate_mismatch
cargo nextest run --locked -p adapter-synthesis a_channel_deviation_alone_names_channel_mismatch
cargo nextest run --locked -p adapter-synthesis a_wrong_rate_delivery_names_rate_mismatch
cargo nextest run --locked -p adapter-synthesis a_stereo_delivery_names_channel_mismatch
cargo nextest run --locked -p adapter-synthesis a_wrong_width_delivery_names_rate_mismatch

# Synthesis delivers real audio through the bound engine (FR-024b);
# a well-formed segment must synthesize — an Err would be the silent branch.
# The same test pins the fail-closed mechanism: an interior NUL cannot
# cross the C FFI boundary → named Unreachable (condition TransportUnreachable)
cargo nextest run --locked -p adapter-synthesis synthesis_delivers_real_audio_and_a_reachable_failure_names_its_condition

# SC-051 mechanism — adapter registered; selector invariant (adapter-scoped)
cargo nextest run --locked -p adapter-synthesis sc_051_registration_makes_offline_default_the_sole_selectable_tier

# CLI: the same checks over the text-I/O protocol
cargo run --locked -p adapter-synthesis -- format-check --rate-hz 22050 --channels 1 --width-bits 32
# → {"capability":"check_format","valid":true}  (exit 0)
cargo run --locked -p adapter-synthesis -- format-check --rate-hz 44100 --channels 1 --width-bits 32
# → verification failed: RateMismatch  (stderr; stdout empty; exit 1)
cargo run --locked -p adapter-synthesis -- delivery-check --rate-hz 22050 --channels 1 --width-bits 32 --pcm-samples 22050 --duration-ms 1000.0
# → {"capability":"check_delivery","valid":true}  (exit 0)
cargo run --locked -p adapter-synthesis -- delivery-check --rate-hz 22050 --channels 1 --width-bits 32 --pcm-samples 100 --duration-ms 1000.0
# → verification failed: RateMismatch  (stderr; stdout empty; exit 1)
printf 'Body text.' | cargo run --locked -p adapter-synthesis -- synthesize
# → {"capability":"synthesize","segment_count":1,"pcm_samples":15488}  (exit 0; ~10 s on this host — model load + single-threaded inference)
```

**Expected outcome** (all nine `nextest` filters pass on this host):
- Happy: a conforming delivery passes `check_format` / `check_delivery` and `AudioChunk::deliver`; `player` converts to device format (only conversion); notification progress accurate (`FR-028`).
- Rate / channel / width deviation: a named closed-set variant (`RateMismatch`, `ChannelMismatch`) with nothing delivered; offer ≤ `MAX_OFFER_MS` (3 000 ms); reason in notification (`FR-037`); mechanism preserved; active fallback deferred (only one selectable tier at v1 — `SC-044`).
- Synthesis: a well-formed segment **delivers** real mono-`f32` @ 22 050 Hz through the bound engine (an `Err` here would be the silent branch); a voice-model load failure or empty result names `InitFailed`, an interior NUL or engine-process death names `Unreachable` — each through `EngineFailure::report` with the segment's echoed position (SC-035).
- `SC-051`: `registered_tiers()` is `[EngineTier::OfflineDefault]`; `is_selectable(TestDouble)` is `false` while this non-`test_double` adapter is registered — verified **scoped to the adapter package**. `cargo nextest run --workspace` cannot run on this host (B1: `alsa-sys` via `player`→`cpal`; B2: `ndk-sys` is Android-only), and `engine-core` is deterministically red (B7) — see the T036 record in `tasks.md:104-120`.

**Reference**: `data-model.md` E2 (validation rules R1, R2); `contracts/adapter-handoff.md` §2–§3; `spec.md:42-45`, `spec.md:85`; `research.md` §6 (condition→variant table); `crates/engine-core/src/closed.rs` 245–270.

### Scenario D — Resume Behavior (`FR-015` / `FR-024a` / `SC-027`)

**What it proves**: The adapter echoes — never computes — the resume anchor: every segment carries its `source_range` as `resume_point`, the v1 declaration plans paragraph/heading resume, and a named failure carries the delivered segment's position verbatim.

**Prerequisites**:
- The `redb` session store + `blake3` fingerprint are owned by `crates/session` (001) — unchanged by, and out of scope of, this adapter.
- **No adapter test named `resume_after_failure` or `resume_after_edit` exists** — replay-window and fingerprint-change behaviour live in the session/player layer (001). The adapter's resume contribution is what it *echoes*, and that is what the commands below pin.

**Commands / checks**:
```sh
# The failure's session position is the delivered segment's source range, verbatim
cargo nextest run --locked -p adapter-synthesis failure_session_position_echoes_the_segment_source_range
cargo nextest run --locked -p adapter-synthesis the_failure_session_position_echoes_the_segment_boundary
cargo nextest run --locked -p adapter-synthesis the_report_constructor_echoes_the_given_position_verbatim

# The v1 declaration plans paragraph/heading resume — never sentence
cargo nextest run --locked -p adapter-synthesis resume_anchor_exhaustive_match_has_no_catchall
cargo nextest run --locked -p adapter-synthesis declared_granularity_is_never_sentence_at_v1
```

**Expected outcome** (all five `nextest` filters pass on this host):
- Resume point = the segment's own `source_range` (`resume_point == Some(source_range)`, §2.1 rule 11), echoed — never adapter-computed (segment-resume CHK030; the `player` is the sole playback authority, `constitution.md:486-490`).
- `plan_for(declared_capabilities())` → `PlayerPlan { ssml: PlainText, resume: ParagraphHeading }` — a declared `None` never upgrades to `FullSsml` / `Sentence` (Principle VI).
- Replay ≤30 s (`FR-015b`), bookmark keying, and edit-clears-bookmark are session-layer (001) guarantees — not exercised by this crate and not claimed here.

**Reference**: `data-model.md` E1 (state transitions); `spec.md:59`, `spec.md:52`; `FR-015`; `FR-036`; `FR-015b`.

### Scenario E — Driving-Safety / Lock-Screen / Focus (`FR-013` / `FR-014` / Principle VIII)

**What it proves**: Playback continues with screen off / locked; control interactions reachable from notification; no required screen interaction; no auto-resume after unexpected end; transient focus ducks ~20%.

**Note**: Adapter does not modify `player` transport / focus / notification logic (`spec.md:137`; Non-Goals). These are verified at `player` / Kotlin `Service` layer, not adapter. Adapter's only contribution is correct audio delivery so mechanism works.

**Quick check (existing `player` mechanism; adapter supports by delivering audio)** — requires the bound engine (T044) and an Android device; **not executable on this host**:
- Lock device; press Play from notification; confirm audio starts within ≤3 s (`SC-009`).
- Trigger transient focus event; confirm duck to ~15–25% (`FR-013`; `constitution.md` §Driving-Safety / ADR-001 deviation clause); resume at boundary when focus regains.
- Trigger permanent focus loss (call); confirm pause immediately; reason expires after 3 s; no auto-resume (`FR-014`; `FR-041`; `FR-023a`).

**Reference**: `spec.md:30-61` (User Stories 1–3); `constitution.md` §Driving-Safety; `AGENTS.md` (§Audio Focus / Driving-Safety — ducking best practice deviation); `spec.md:137` (adapter out of scope for notification/focus).
