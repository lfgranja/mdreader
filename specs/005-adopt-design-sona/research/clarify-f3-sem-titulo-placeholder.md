# Clarification F3 — "Sem título" placeholder for missing title/section metadata

> **Feature:** `specs/005-adopt-design-sona` (US1/US3/US4 metadata card; edge case "documento não tem título ou seção"; closed 9-element SurfaceInventory, `data-model.md` §SurfaceInventory)
> **Question:** The spec only says "exibe placeholder estável para o título; não exibe seção antes do primeiro heading." The exact placeholder token/copy, its pt-BR wording, its TalkBack announcement (what should be announced when a document has no title?), and whether the placeholder counts inside the closed 9-element inventory are undecided. Options: (A) visible em-dash/silent placeholder, aria uses semantic fallback label; (B) visible pt-BR fallback copy "Sem título" styled as hush text, announced as-is; (C) rustic omit — bind not rendered when title absent (needs closed-inventory clause); (D) upstream authority ensures title never empty (filename-only titles), reserving the decision to the section side only.
> **Scope:** research note; not a spec amendment. Informs a clarification decision only.
> **Method (2026-10-24):** NN/g empty-state guidance; Material Design 3 empty-state/placeholder guidance; web.dev CLS research (reserved space, stable placeholders); W3C Understanding 4.1.2 (Name, Role, Value) + 1.3.1 (Info and Relationships) + ARIA `aria-label`/`aria-placeholder` APG; Material Design 3 text-field placeholder semantics; pt-BR UI string conventions (open-source + system apps); NHTSA Phase 1/2 driver-distraction guidelines (30-char reading lockout, ≤2 s glance / ≤12 s task) + Google Design for Driving (≤120 chars) + ISO 15006/15007 (visual behaviour measurement). All URLs below are primary or peer-reviewed where cited; pt-BR evidence is inconclusive and flagged.

## 1. What the spec currently says (and what is undecided)

- `spec.md` Edge Cases: "Como o sistema se comporta quando o documento não tem título ou seção? → Exibe placeholder estável para o título; não exibe seção antes do primeiro heading."
- `data-model.md` §SurfaceInventory: element 2 is "Metadata card — static title + current section on `--sona-stage`". The inventory is closed: "Any element not listed here (visible, hidden, or dead) = inventory violation (SC-001 item (ii) fails)."
- `contracts/status-surface.md` S4: "The StatusView contains EXACTLY … 9 elements; extra/hidden/dead = failure."
- Undecided: (i) the visible placeholder token (em-dash vs. copy vs. omit); (ii) the pt-BR wording; (iii) the TalkBack announcement when the document has no title; (iv) whether a placeholder is a 10th element or content of element 2.

## 2. Empty/placeholder text conventions (web)

- **NN/g** (https://www.nngroup.com/articles/empty-state-interface-design): "Do not default to totally empty states … creates confusion … If there is no relevant data to display after a process has completed, use the empty space to provide a system-status message in the empty space that briefly states that no content is available." And on placeholders specifically (https://www.nngroup.com/articles/form-design-placeholders): placeholders are unreliable for AT ("not all screen readers will announce the placeholder attribute") and disappear on input — so a *visible* placeholder that carries meaning must be real text, not the HTML `placeholder` attribute.
- **Material Design 3** (https://m3.material.io/components/text-fields/specs; empty-states doc https://m2.material.io/design/communication/empty-states.html): empty states are "placeholders that appear when a component has no content to display"; they "communicate what will appear there, why there isn't content." M3 text fields use placeholder as a *hint about expected format*, never as the label; the label must be persistent. Implication: a missing-value placeholder is acceptable as *hint*, but the accessible name must come from a persistent label/`aria-label`, not from the placeholder glyph.
- **web.dev CLS** (https://web.dev/articles/optimize-cls; https://web.dev/articles/cls): layout shifts come from inserting content without reserved space; "Try to avoid collapsing the reserved space by showing a placeholder if, for example, no ad is returned. Removing the space set aside for elements can cause just as much CLS as inserting content." And on text: "We can't explicitly set a width or height on text … with a web font that's causing a layout shift, we'll need to approach it from a different angle" (fallback-font metric matching). Implication for this surface: the title slot must keep a *stable, fixed advance* placeholder so the metadata card does not reflow when a title is absent vs. present; a single-glyph token (em-dash) is the most metric-stable choice because its advance is one cell and does not depend on the eventual title's length (the title is known at session start, so no mid-session reflow — but the placeholder must still be *deterministically* the same width class across renders for the host census).
- **Mobbin/UX Planet** (https://mobbin.com/glossary/empty-state): "Avoid lazy placeholder text … Don't be generic with messaging, avoid placeholders like 'no data', or 'empty here'." Balanced against the driving constraint (§5): on a glance surface, generic-but-short beats contextual-but-long.

## 3. Accessibility semantics — what should TalkBack announce?

- **WCAG 2.1 SC 4.1.2 Name, Role, Value** (https://www.w3.org/WAI/WCAG21/Understanding/name-role-value): "the name and role can be programmatically determined … notification of changes … available to user agents, including assistive technologies." For scripted controls, the sufficient techniques (ARIA4/ARIA5/ARIA14/ARIA16) require the accessible name to be present and valid. A visible em-dash alone gives the AT the name "—" (announced as "em dash" or skipped), which is not a *meaningful* name — it fails the spirit of 4.1.2 for a user who cannot see the glyph.
- **WCAG 2.1 SC 1.3.1 Info and Relationships** (https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships): structure/meaning conveyed visually must be available programmatically. The "no title" state is information; it must reach AT.
- **W3C APG — Providing Accessible Names and Descriptions** (https://www.w3.org/WAI/ARIA/apg/practices/names-and-descriptions): `aria-label` is the sanctioned way to give a programmatic name to an element whose visible content is not a usable name (e.g., an icon or a glyph). Precedence: `aria-labelledby` > `aria-label` > visible text. So when the visible placeholder is "—", the element should carry `aria-label="Sem título"` (pt-BR) so TalkBack announces the *state*, not the glyph.
- **MDN `aria-placeholder`** (https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Attributes/aria-placeholder): "A placeholder is text that appears in the form control when it has no value set … Authors SHOULD NOT use `aria-placeholder` instead of a label … The label indicates what kind of information is expected; the placeholder text is a hint about the expected value." This directly supports *decoupling* the visible placeholder (hint/glyph) from the accessible name (label/"Sem título").
- **WAI-ARIA 1.2** (https://www.w3.org/TR/wai-aria-1.2): same normative note — `aria-placeholder` is not a label substitute.
- **Conclusion for semantics:** the visible placeholder and the AT announcement should be *different strings*: visible = minimal stable glyph ("—"); AT = meaningful pt-BR state ("Sem título"). This is the only option that satisfies both 4.1.2 (meaningful name) and the driving constraint (minimal visible text) at once.

## 4. pt-BR copy conventions

- **Conventional fallback in pt-BR UIs:** file managers, media players, and document apps in pt-BR conventionally render a missing title as "Sem título" (or parenthesised "(sem título)"). This mirrors the English "Untitled" convention localised to pt-BR; it is the string a Brazilian user expects to see for an unnamed document.
- **W3C i18n** (https://www.w3.org/TR/international-specs; https://www.w3.org/International/i18n-drafts/nav/about): no normative pt-BR placeholder vocabulary is published by W3C; missing-value display is left to the application. The W3C i18n guidance covers language/direction metadata and locale fallback, not copy.
- **Honest limit:** I found **no primary, peer-reviewed, or authoritative source** that pins a canonical pt-BR string for a missing *media/document title* on a driving surface. "Sem título" is the conventional, widely-understood fallback and is what pt-BR users expect, but it is a *convention*, not a standard. If the maintainer prefers a different register (e.g., "Documento sem título", "Sem nome", or the em-dash alone), the change is a one-token edit; the evidence here does not lock the wording. Residual uncertainty is recorded in §7.

## 5. Driving-surface filter (NHTSA / ISO 15006 / 15007)

- **NHTSA Phase 1 guidelines** (https://www.nhtsa.gov/sites/nhtsa.gov/files/distraction_npfg-02162012.pdf; Federal Register 78 FR 24818, https://www.federalregister.gov/documents/2013/04/26/2013-09883/visual-manual-nhtsa-driver-distraction-guidelines-for-in-vehicle-electronic-devices): per-se lockout on "reading more than 30 characters (not counting punctuation marks … counting each number, no matter how many digits, as one character)" of visually presented text during a single task; glance budget ≤2 s per glance, ≤12 s per task; manual text entry ≤6 key presses. A placeholder that is *read* by the driver must therefore be ≤30 chars; "Sem título" (10 chars) and "—" (1 char) both pass; a longer explanatory placeholder (e.g., "Documento sem título disponível") would risk the 30-char lockout and is rejected.
- **Google Design for Driving** (https://developers.google.com/cars/design/design-foundations/writing-principles): "Limit text to 120 characters" and "People don't read what's on the screen; instead they scan"; content must be "glanceable, consistent, clear." A missing-title placeholder should be the *shortest* stable token, not a sentence.
- **ISO 15006** (auditory, https://www.iso.org/standard/34885.html) and **ISO 15007** (visual behaviour measurement, https://www.iso.org/standard/56621.html; ISO 15007:2020 supersedes 2014): define the measurement of driver visual behaviour (glance duration, number of glances) for TICS. They do not prescribe placeholder copy; they are the *measurement frame* the 2 s/12 s NHTSA bounds sit in. No ISO clause requires a placeholder; the constraint is metric (glance time), not lexical.
- **NHTSA Phase 2** (portable/aftermarket, per Dykema summary https://www.dykema.com/news-insights/nhtsa-issues-driver-distraction-guidelines-for-portable-and-aftermarket-devices.html): per-se lockouts include "Displaying text for reading from books, periodical publications, Web page content, social media content, text-based advertising and marketing, or text-based messages." A document title is *not* in that prohibited list (it is a metadata label, not reading material), so displaying a short title/placeholder is permitted; the constraint is length, not presence.
- **Implication:** the driving constraint is on *length and glance cost*, not on whether a placeholder exists. The shortest stable token wins: "—" (1 char, fixed advance, zero reading cost) over "Sem título" (10 chars) for the *visible* surface; the meaningful string belongs in the AT channel, not on the glass.

## 6. Options comparison

| Option | Visible placeholder | AT announcement | Inventory impact | Driving-safety | A11y (4.1.2/1.3.1) |
|---|---|---|---|---|---|
| (A) visible em-dash + semantic fallback label | "—" (1 glyph, fixed advance) | `aria-label="Sem título"` (meaningful, pt-BR) | None — placeholder is *content* of element 2 | Best: 1 char, zero reading cost, no CLS | Best: meaningful name decoupled from glyph |
| (B) visible "Sem título" as hush text, announced as-is | "Sem título" (10 chars) | "Sem título" (same string) | None — content of element 2 | OK: 10 chars ≤30, but higher glance cost than (A) | Good: meaningful, but visible=AT (no decoupling) |
| (C) rustic omit — bind not rendered when title absent | (none) | (none / "no title" implied by absence) | **Requires clause**: conditional bind changes the census (element 2 sometimes absent); host audit must allow "title sub-node optional" | Best: zero text | Weakest: absence is not a *name*; AT gets nothing programmatically (fails 4.1.2's "name can be determined") |
| (D) upstream ensures title never empty (filename-only) | (never missing) | (always the real title) | None — title always present | Best: no placeholder ever | Best: real name always present; but it is a *data-model* decision, not a UI convention, and filenames are not titles |

## 7. Recommendation

**Option (A) — visible em-dash "—" + `aria-label="Sem título"` (pt-BR) on the title slot.** It is the only option that simultaneously (i) keeps the closed 9-element inventory unchanged (the placeholder is *content* of element 2, "Metadata card", not a new element — no inventory clause needed, unlike (C)); (ii) satisfies the driving constraint (1 glyph, fixed advance, zero reading cost, no CLS — NHTSA 30-char lockout and Google ≤120-char limit are met with margin); (iii) satisfies WCAG 4.1.2/1.3.1 by giving TalkBack a meaningful pt-BR name via `aria-label`, decoupled from the glyph, per W3C APG + MDN `aria-placeholder` guidance; and (iv) matches pt-BR convention for the *announcement* while keeping the glass minimal. Option (B) is acceptable but costs more glance time for no a11y gain; (C) fails 4.1.2 (absence is not a name) and complicates the host census; (D) is the cleanest long-term but is an upstream data-model decision (filename-as-title) outside this surface's scope and would make the placeholder dead code — worth a separate, later decision, not this clarification.

**Suggested spec wording** (edge case, pt-BR, to replace the current one-liner):

> "Quando o documento não tem título: o slot de título exibe o placeholder estável '—' (um glifo, avanço fixo, sem deslocamento de layout) pintado em `--sona-hush`; o elemento carrega `aria-label="Sem título"` para que leitores de tela anunciem o estado (e não o glifo). O placeholder é *conteúdo* do elemento 2 (Metadata card), não um décimo elemento. Quando o documento não tem seção (antes do primeiro heading): o sub-slot de seção não é renderizado (ausência intencional, não placeholder); a Metadata card permanece com apenas o título. A ausência de seção é um estado de renderização documentado, não uma violação de inventário."

**Residual uncertainty:** (1) the pt-BR wording of the aria label is convention-based, not standardised — "Sem título" is recommended but "Documento sem título"/"Sem nome" remain defensible one-token edits (§4); (2) whether to also adopt (D) upstream (filename-only titles) to make the placeholder unreachable is a separate data-model decision, deferred; (3) the section's conditional absence should be recorded in `contracts/status-surface.md` S4 as an allowed rendering state so the host census does not flag it. (4) TalkBack's actual announcement string for `aria-label` on a text node inside a WebView must be confirmed in the device trial (SC-007 leg), mirroring the D5 verification split.
