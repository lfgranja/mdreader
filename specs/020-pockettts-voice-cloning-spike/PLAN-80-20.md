# 020 — PocketTTS voice cloning spike (80/20, device-first)

Status: draft (2026-11-15). Goal: decidir viabilidade de **voz clonada offline pt-BR** com **TTFA competitivo** no `2201117TY` (Redmi Note 11, SD680, Android 13) para mdreader.

## Contexto (evidência)
- Baseline atestado: Piper/sherpa-onnx `play_to_audio_ms = 1551 ms` (T051/T052, `verification/T051_T052_attestation.md`).
- `tts-work/`: referência Sona pt-BR preparada (`youtube_ref/reference_sona_ptbr_20s.wav`, 20 s, 24 kHz mono PCM16, limpa) mas **sem embedding/modelo integrado**; experimento Pocket-TTS 4.0.1 (Python, EN) mostrou warm TTFA de síntese ~267–414 ms no host com custos únicos altos (load ~2,85 s, estado de voz ~6,97 s).
- Pipeline mdreader atual: Piper VITS-only (`crates/adapter-synthesis/src/synth.rs`), handoff **mono f32 @ 22050 Hz** (`engine-core/src/format.rs`), vozes Piper fechadas, sem API de referência/embedding, sem streaming de chunks no adapter. `sherpa-onnx` 1.13.8 + vendor sys expõem structs Pocket (`reference_audio`, `voice_embedding_cache_capacity`) mas binding safe usado é VITS.
- Web: PocketTTS suporta Português (Kyutai) e clonagem zero-shot sem transcript; sherpa-onnx suporta PocketTTS (`generateWithCallback`, `num_steps`, cache de embedding) com bundle oficial EN `sherpa-onnx-pocket-tts-int8-2026-01-26`; bundle pt no layout sherpa existe em `haex-space/pocket-tts-sherpa-onnx` (fix BOS para sherpa 2.0.1). Benchmark público SD845: RTF ~0,94–1,06 (TTFA 1º chunk não reportado). **TTFA no SD680: NÃO VERIFICADO.**

## Decisão gate (go/no-go por medição)
- **GO** para spike de integração: no 2201117TY, com referência Sona 20 s e texto pt-BR curto/longo, **TTFA 1º áudio audível** (cold e warm, engine/voz em cache) ≤ ~1551 ms **e** RTF < 1 sustentado **e** RSS/estabilidade aceitáveis.
- **NO-GO**: latência/memória pior que baseline ou instável → manter Piper; tratar clonagem como bake-offline/voz Piper custom ou dependente de hardware melhor.

## Ciclo 80/20 (ações)
### Fase 0 — Desbloqueio medição (pré-requisito)
- Reconectar device `adb-53cf9aa7-4VfOJ6._adb-tls-connect._tcp`.

- Selecionar bundle PocketTTS pt compatível com runtime sherpa disponível: testar `haex-space/pocket-tts-sherpa-onnx/pt` (verificar compatibilidade com sherpa 1.13.x vs necessidade de ≥2.0.1/fix BOS).

- Registrar resultados em `specs/020-pockettts-voice-cloning-spike/measurements.md` e comparar com 1551 ms.

### Fase 2 — Spike de integração (somente se GO)
- Introduzir backend/driver PocketTTS em `adapter-synthesis` (config com `reference_audio` + cache de embedding, `generate_with_callback` para streaming) atrás de interface compatível com produção segmentada.
- Resolver formato: preferir **resample 24→22050 Hz mono f32 no adapter** inicialmente para evitar refatoração global; só evoluir `DeclaredFormat`/player se houver ganho comprovado.
- Representar voz clonada (referência/embedding persistido) sem quebrar `VoiceId` fechado (extensão controlada do vocabulário/contratos + docs + testes).
- Packaging Android: assets de modelo + referência, tamanho, extração, licença/consentimento.
- Diagnósticos: `play_to_audio_ms`, `voice_state_ms`, engine metrics para voz clonada.

### Fase 3 — Fallback (se NO-GO)
- Otimizar TTFA Piper (prewarm, segmentação/handover, profiling no device).
- Avaliar trilha bake/custom Piper 22.050 Hz apenas se houver dados e direitos claros.

## Riscos
- **Dispositivo:** SD680 pode não sustentar RTF<1/TTFA baixo com modelo neural de clonagem.
- **Compatibilidade:** mismatch sherpa 1.13.8 ↔ exports recentes (BOS/formatos); demo Android oficial imatura.
- **Licença/consentimento:** Kyutai weights gated (CC-BY-4.0 + termos), vozes de terceiros, uso de áudio extraído de vídeo — verificar antes de distribuir.
- **Qualidade pt-BR:** clonagem com ref Sona e inteligibilidade em texto longo não validadas.
